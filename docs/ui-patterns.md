# 화면 구성 규칙 (디자인 시스템 v1.0 적용 기준)

모든 화면은 `src/components/ui.tsx`의 부품만으로 조립한다. 화면 파일에서 새 모양(색·모서리·그림자·글자 크기)을 직접 만들지 않는다.

## 1. 내용 종류 → 부품 대응표

| 내용 | 부품 | 디자인 시스템 근거 |
|---|---|---|
| 홈 첫 화면 | `HeroPanel` (남색 큰 상자: eyebrow → 제목 → 설명 → 검색 → 예시 질문) — **사용자 확정(2026-11-19)**, 홈에서만 사용 | 브랜드 Navy 950 |
| 화면 맨 위 제목(홈 외) | `PageHeader` (eyebrow → 제목 → 설명 → 상태 배지) | Overview |
| 구역 제목 | `Section` (제목 · 설명 · 오른쪽 kicker 또는 "자세히 보기 →") | section-head |
| 검색·질문 입력 | `SearchPanel` / `Field` (라벨 → 입력칸 → 도움말 → 검증 메시지) + 글자 버튼 | 입력 컴포넌트 |
| 고르기(사업 유형·단계·자료 종류) | `SelectField` | 입력 컴포넌트(select) |
| 항목 목록(서비스·분쟁 유형·검색 결과·서류·상담 기록·사건) | `CaseCard` (배지 2개 → 제목 → 설명 → 구분선 아래 정보 · "→") | 카드 및 요약 |
| 순서·절차·진행 단계 | `StepList` (번호 원 · 제목 · 설명 · 오른쪽 상태 배지) | 사건 관리 UI 패턴 |
| 법령·판례 근거 | `LegalCard` (관련 법령 + 공식 출처 연결 배지 → 조문 → 요약 → 안내 → 원문 보기·인용 복사 → 메타데이터) | 법률 근거 표시 |
| 기한·자료 비교 | `DataTable` (모바일 가로 스크롤) | 데이터 테이블 |
| 안내·주의·검토 필요 | `Alert` info / warn / danger | 상태 배지 및 알림 |
| 요약 숫자 | `MetricCard` (큰 숫자 → 굵은 제목 → 작은 설명) | Overview metric |

## 2. 색 의미 (색만으로 뜻을 전달하지 않고 항상 글자와 함께)

| 색 | 쓰는 곳 |
|---|---|
| Navy 950 | 사이드바·브랜드, 홈 `HeroPanel` |
| Blue 600 | 화면당 하나뿐인 주요 버튼, 현재 메뉴, eyebrow, 단계 번호 |
| 배지 파랑 | 분류·진행 중 |
| 배지 초록 | 완료·공식 출처 연결 |
| 배지 노랑 | 기한·확인 필요 |
| 배지 빨강 | 긴급·검토 필요 |
| 배지 회색 | 대기·준비 중 |
| 배지 보라 | 전문가 검토 |

## 3. 버튼

- 화면당 Primary(파랑)는 가장 중요한 행동 하나.
- 나머지는 Secondary(흰 바탕 테두리) 또는 Ghost(글자만).
- 삭제처럼 되돌릴 수 없는 행동은 Danger + 확인 단계.

## 4. 글자 크기

| 역할 | 크기 |
|---|---|
| 화면 제목 | 24px(폰) / 30px(태블릿 이상) |
| 구역 제목 | 17px / 19px |
| 카드 제목 | 14px 굵게 |
| 본문·설명 | 14px / 카드 설명 13px |
| 보조·메타 | 11px |
| 배지 | 11px 굵게 |

## 5. 금지

- 디자인 시스템에 없는 모양: 아이콘 타일, 둥근 칩 버튼(홈 `HeroPanel` 예시 질문 제외), 말풍선, 색칠한 강조 상자
- `HeroPanel`을 홈 밖에서 쓰거나 비슷한 남색 상자를 새로 만드는 것
- 카드 안 장식 아이콘
- 한 화면에 파란 버튼 2개 이상
